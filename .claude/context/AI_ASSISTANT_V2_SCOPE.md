## 2. 설계(java-cms 와 같은 원칙, Laravel/Filament 로 번역)

1. **모델은 제안만, 쓰기는 사람이**: 도구 호출 `open_admin_page(resource)`·`propose_popup`·`propose_post`·`propose_page`·`propose_banner`(필요하면 `propose_image`)는 **실행하지 않고** 서버가 검증해 "행동 카드"로 대화에 붙인다. 카드의 버튼은 해당 Filament **Create 페이지로 가는 GET 링크 + `?ai_proposal=<id>`** — 그 페이지의 `mount()` 가 제안(소유자·만료·종류 확인)을 읽어 폼 필드에 **값만 채운다(저장 안 함, 비공개/비활성 상태로)**. Filament 가 그 페이지의 권한(`canCreate`/정책)을 이미 확인하므로 **권한 우회 경로가 없다**(쓰기 전용 AI 엔드포인트를 만들지 않는다). 카드와 시스템 지시문의 메뉴·리소스 목록은 **현재 관리자가 접근할 수 있는 것만**(`canAccess`/`canCreate`/`admin_role` 기준 - 실제 코드를 읽어 판단).
2. **이미지까지 한 번에**: 팝업·배너·페이지 카드는 "이미지 1장 생성(비용 안내)" 버튼 하나 → Livewire 액션이 소유자·만료·상태를 확인하고 `AiChatService` 로 이미지 생성(한도 적용) → 제안 행에 이미지 경로 저장 → 작성 화면으로 이동(`?ai_proposal=`, 폼의 이미지 필드까지 채워짐). 팝업 검증(제목 길이·날짜 형식)을 먼저 끝낸 뒤 이미지를 만든다. 이미지 프롬프트의 개행·제어문자는 서버가 공백으로 바꾸고 길이를 자른다.
3. **한 번만 호출**: 도구 결과를 모델에 되돌려 보내는 왕복 없음. `tools`+`systemInstruction`(OpenAI 는 system 메시지, `parallel_tool_calls:false`)을 보내고 응답의 모든 파트에서 텍스트와 호출을 모은다. 텍스트가 비면 서버가 고정 문구를 합성, 이력에는 카드를 **평문 한 줄 요약**으로만 남김(빈 content 금지). 카드 3장 이하·중복 제거. 빈 후보·안전 차단·잘못된 도구 인자(OpenAI `arguments` 는 JSON 문자열)는 **재시도 없이** 일반 오류 문구. `AiProviderContract` 는 새 메서드(중립 모델: 시스템 문장·턴 목록·도구 선언 → 텍스트+호출 목록)를 더하고 기존 `chat()` 은 위임(기존 시험 보존). 도구가 안 되는 모델이면 도구 없이 일반 대화로 내려가는 **폴백** 능력 플래그.
4. **한도(없던 것)**: 새 테이블 `ai_chat_usage`(관리자·제공자·종류(chat/image)·시각, 대화 삭제와 무관하게 남음) — 제공자 호출 **직전에 먼저 기록 → 오늘 건수(관리자별·사이트 전체)를 센 뒤 초과면 되돌림**(동시 요청 경쟁 방어, 관리자별 동시 1건 가드), 단위는 제공자 호출 1회. 한도 설정 키(`ai_chat_daily_limit`·`ai_image_daily_limit` 등)를 `SiteSettings` AI 탭에 추가(`SiteSettingSeeder`·`SiteSettings.php` 838줄 그룹 매핑 포함, 기본값은 보수적으로), `PruneAiChatHistory` 가 이 표도 정리.
5. **제안 저장 = 새 테이블 `ai_chat_proposals`**(`message_id` FK cascade, 종류, 페이로드(서버가 검증·정규화한 값), 상태 `proposed/image_ready/used/expired`, 만료(1시간), 이미지 경로, 생성 시각): 소유자(제안→메시지→대화→`user_id` = 현재 관리자; 슈퍼관리자의 `AiChatLogResource` 열람 화면에서는 **읽기 전용·버튼 없음**), 만료, 원자적 상태 전이. `Create*` 페이지의 `ai_proposal` 처리는 소유자·만료·종류만 확인하고 폼에만 채운다.
6. **입력 안전**: 본문은 모델이 준 **평문만** 받아 서버가 이스케이프해 `<p>` 로 감싼다(에디터형 필드; 정제기의 외부 `<img>`/`<a>` 허용에 의존하지 않음 - 프롬프트 인젝션으로 추적 이미지·피싱 링크가 공개 화면에 심기는 것 방지; 기존 `HtmlSanitizerService` 는 저장 때 그대로 돈다), 날짜는 서버가 변환·검증(상대 오프셋 우선), 제목은 개행·제어문자 제거·길이 제한(감사 로그 라벨도 같은 이유), 게시판은 서버가 존재·쓰기 가능 여부 확인. 채팅 마크다운은 굵게·기울임·목록·코드·**http/https 링크만**(`rel="noopener noreferrer nofollow"`), **이미지는 렌더하지 않는다**(대화 내용이 URL 쿼리로 유출되는 통로), Blade 에서 신뢰할 수 없는 문자열을 `{!! !!}` 로 찍지 말 것(CSP 와 Blade 출력 규칙을 코드로 확인).
7. **시스템 지시문**: 요청마다 서버가 만든다 — 현재 날짜·시각·시간대 + 관리자 화면 지도(리소스·페이지 이름과 "할 수 있는 일" 한 줄, **URL 은 넣지 않는다**(관리자 경로 `config('app.admin_path')` 는 외부 제공자로 나가면 안 됨; 모델에는 키만 주고 URL 은 서버가 만든다), **현재 관리자가 접근 가능한 것만**) + 규칙(한국어·없는 기능을 지어내지 않음·행동은 도구로 제안만·개인정보를 적지 말라는 안내) + 현재 열려 있는 작성 화면 종류(허용 목록으로 검증, `HasAiFormFill` 의 기존 `targetTextFields()` 표와 일치). 설명 문구는 코드 한 곳(예: 리소스에 붙인 메타데이터 또는 전용 서비스 상수)에 두고 **"도구에 노출되는 모든 키는 설명 보유"** 시험으로 고정.
8. **UI(Livewire 위젯 재설계 + 감독/설정 화면)**: 말풍선·전송 중 표시(`wire:loading`)·안전한 마크다운·추천 질문 칩("팝업 만들어줘"·"이 화면에 채울 글 써줘" 등, 대상 24px+)·행동 카드(상태·버튼·비용 안내·읽기 전용 모드)·대화 목록 압축·스크롤/포커스·접근성(WCAG 2.2 AA: `role="log"`/`aria-live`, 키보드, 대비, `prefers-reduced-motion`)·라이트/다크(Filament 테마 변수 사용, 하드코딩 색 금지)·위젯 CSS 를 blade 안 `<style>` 에서 분리(프로젝트의 CSP·자산 규칙 확인). **잔여량 표시**: 입력창 근처 "오늘 남은 질문 N회", 이미지 카드·버튼 근처 "오늘 남은 이미지 N장"(`ai_chat_usage` 로 API 호출 없이 계산, 전송마다 갱신, 0 이면 막고 안내), 사이트 설정 AI 탭에 오늘 사용량 요약, `AiChatLogResource` 목록에 관리자별 오늘 사용량. 제공자 크레딧 잔액은 표시하지 않는다(조회 수단이 없는 것으로 알고 있다 - 미확인으로 보고, 화면에는 "우리 사이트의 일일 한도 기준"이라고 쓴다).
9. **글 채우기(이미 있는 기능의 정비)**: 열린 작성·수정 화면에서 AI 답변마다 "○○에 채우기"(`HasAiFormFill`)는 그대로 두되 ①허용 필드 표 시험으로 고정 ②채운 칸 표시·안내 ③서버가 저장하는 코드 경로가 없음을 정적 시험으로 고정(예: 채우기 코드에 `save()`·`create(`·`update(` 호출 없음) ④본문은 평문→`<p>` 변환 규칙 통일.
10. **감사·개인정보·문서**: 팝업 등 저장은 기존 감사 로그가 남고 제안 id 를 `detail` 에 더함. 대화·카드에 개인정보가 들어갈 수 있음을 사이트 설정 AI 탭 안내문에 명시(대화 내용이 외부 제공자로 전송됨). 기존 문서(README·`PROJECT.md`·`.claude/context/PROJECT_STATUS.md` 는 건드리지 않고 `AI_V2_NOTES.md` 에 "갱신할 문서 문장" 목록)를 grep 으로 찾아 어긋난 문장을 정리해 보고.
